# git push и git pull

Пока всё происходило на твоём компьютере. Пора отправить работу в интернет — и научиться забирать чужую.

## Remote: куда отправлять

Remote — это «адрес» удалённого репозитория. Обычно он называется `origin` (это просто имя, как «папка с файлами»), и ссылка на него приходит, когда ты клонируешь проект.

```bash
git remote -v
# origin  git@github.com:user/project.git (fetch)
# origin  git@github.com:user/project.git (push)
```

Добавить вручную, если проект создан локально:

```bash
git remote add origin git@github.com:user/project.git
```

## git push: отправить свои коммиты

```bash
git push -u origin main
```

- `-u` (`--set-upstream`) запоминает связку «локальная ветка main → origin/main». После этого достаточно просто `git push`.
- Push отправляет **только закоммиченное**. Незакоммиченные изменения сидят дома.

:::warning Push ≠ commit
`git commit` сохраняет локально, `git push` отправляет на сервер. Очень частая ситуация у новичков: «я же коммитил, почему на GitHub пусто?» — потому что не запушил.
:::

## git pull: забрать чужое

```bash
git pull
```

Это `git fetch` (скачать новое) + `git merge` (влить в текущую ветку). Если коллега поменял файл, который ты тоже менял, — получишь конфликт; как его решать, разберём в модуле про ветки.

Полезная привычка: **начинай день с `git pull`**, чтобы не разбираться с кучей конфликтов вечером.

## Типичный рабочий цикл

```bash
git pull                    # забрать, что сделали другие
git switch -c fix/typo      # отдельная ветка под задачу
# ... правишь файлы ...
git add .
git commit -m "fix: опечатка в заголовке"
git push -u origin fix/typo  # отправить ветку и открыть Pull Request
```

## Что делать, если push отклонили

```
! [rejected]  main -> main (fetch first)
```

Значит, на сервере есть коммиты, которых у тебя нет. Решение почти всегда одно: `git pull`, разобраться, и снова `git push`.

:::danger Только не --force
`git push --force` перезаписывает историю на сервере и может стереть чужую работу. В команде его применяют только к своим личным ветками и только осознанно.
:::

## Мини-практика

В терминале ниже уже есть репозиторий с коммитом и настроенным remote `origin`. Твоя задача:

1. `git status` — посмотреть состояние.
2. Создать файл: `echo "release notes" > RELEASE.md`.
3. `git add .` и `git commit -m "docs: add release notes"`.
4. `git push -u origin main` — отправить на remote.
5. `git status` — убедиться, что ветка в синхронизации.
