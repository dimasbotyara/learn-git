# git add и git commit

Два шага, из которых состоит почти вся ежедневная работа. Разберём их по порядку — и сразу потрогаем руками в терминале ниже.

## Staging area: корзина перед отправкой

Представь, что ты отправляешь посылку. Ты же не бросаешь в коробку всё, что лежит на столе, — сначала **выбираешь, что положить**. Staging area (она же «индекс») — это та самая коробка.

- Рабочая папка — всё, что лежит на столе.
- Staging area — то, что уже в коробке.
- Коммит — заклеенная посылка с наклейкой «что внутри».

`git add` кладёт файлы в коробку, `git commit` заклеивает её.

```bash
git add notes.txt      # один файл
git add src/           # целая папка
git add .              # всё, что изменилось
```

:::note Зачем вообще разделять?
Иногда ты поменял пять файлов, но закоммитить хочешь только два: например, фикс бага отдельно от эксперимента. Staging area даёт выбрать.
:::

## git commit: снимок с подписью

```bash
git commit -m "docs: add install instructions"
```

`-m` — сообщение коммита. Оно попадёт в историю, и через полгода (или для коллеги) это будет единственное объяснение, **что** и **зачем** ты сделал.

## Почему «fix» и «update» — плохие сообщения

Сравни два варианта истории:

```bash
git log --oneline
# a1b2c3d fix
# 9f8e7d6 update
# 5c4b3a2 oops
# 1a2b3c4 fix again
```

и

```bash
git log --oneline
# a1b2c3d fix: не открывается меню на iOS 17
# 9f8e7d6 feat: добавлена тёмная тема
# 5c4b3a2 test: покрытие для парсера дат
# 1a2b3c4 docs: описана установка через venv
```

Во втором случае ты через месяц сразу понимаешь, где искать. Хорошее сообщение отвечает на вопрос «что изменится для пользователя проекта».

:::tip Простой шаблон
`тип: что сделано` — например `fix: падение при пустом файле`, `feat: экспорт прогресса`, `docs: пример .gitignore`.
Пиши в повелительном наклонении: «add», «fix», а не «added», «fixed».
:::

## Смотрим, что получилось

```bash
git status              # что в коробке, что на столе
git log --oneline       # история коммитов
git diff                # изменения, которые ещё не в коробке
git diff --cached       # изменения, которые уже в коробке
```

## Мини-практика

Выполни по шагам в терминале ниже:

1. `git init` — создать репозиторий.
2. Создать файл: `echo "первый коммит" > notes.txt` (или `touch notes.txt`).
3. `git status` — посмотреть, что файл untracked.
4. `git add notes.txt` — положить в корзину.
5. `git commit -m "docs: add notes"` — зафиксировать.
6. `git log --oneline` — увидеть свой коммит.

Как выполнишь — задание подсветится зелёным, и можно идти дальше.
