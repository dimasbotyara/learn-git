# SSH-ключи без боли

Пароль при каждом `git push` — главная причина, по которой люди ненавидят Git. SSH-ключ решает это раз и навсегда: один раз настроил — и больше ничего не спрашивают.

## Как это устроено

У тебя есть **две** половинки ключа:

- **закрытый** (`id_ed25519`) — лежит только на твоём компьютере, никому его не показывай;
- **открытый** (`id_ed25519.pub`) — его можно смело публиковать, он и загружается на GitHub.

GitHub хранит открытый ключ. При подключении ты доказываешь, что у тебя есть закрытый — и сервер тебя узнаёт.

## Шаг 1. Сгенерировать ключ

```bash
ssh-keygen -t ed25519 -C "you@example.com"
```

- `-t ed25519` — современный и короткий тип ключа (лучше старого `rsa`);
- `-C` — комментарий, удобно указать почту;
- на вопрос про путь — Enter (по умолчанию `~/.ssh/id_ed25519`);
- passphrase можно оставить пустой, а можно задать — тогда её спросят один раз за сессию.

Получится два файла: `~/.ssh/id_ed25519` (закрытый) и `~/.ssh/id_ed25519.pub` (открытый).

## Шаг 2. Скопировать открытый ключ

```bash
cat ~/.ssh/id_ed25519.pub
```

Скопируй **всю строку целиком**, начиная с `ssh-ed25519`.

## Шаг 3. Добавить на GitHub

- Открой **Settings → SSH and GPG keys → New SSH key**.
- Title — любой (например, «Рабочий ноутбук»).
- Key type — `Authentication Key`.
- Вставь строку и сохрани.

## Шаг 4. Проверить

```bash
ssh -T git@github.com
# Hi username! You've successfully authenticated...
```

Если увидел приветствие — всё работает. Фраза `but GitHub does not provide shell access` — это нормально, так и должно быть.

:::tip Лёгкий путь, если GitHub CLI уже авторизован
Если у тебя установлен `gh` и ты в него залогинен, можно не ходить в браузер:

```bash
gh auth login          # выбрать SSH
gh ssh-key add ~/.ssh/id_ed25519.pub
```

`gh` сам и ключ создаст, и на GitHub загрузит.
:::

## Одна проблема, которую все встречают

```bash
git clone git@github.com:user/project.git
# Permission denied (publickey)
```

Причины по частоте:

1. Ключ не добавлен на GitHub (шаг 3).
2. Ты клонировал по HTTPS, а ключ настроен для SSH: `git remote -v` покажет адрес; исправить — `git remote set-url origin git@github.com:user/project.git`.
3. Агент SSH не знает про ключ: `ssh-add ~/.ssh/id_ed25519`.

:::danger Никогда не публикуй закрытый ключ
В `id_ed25519` нет `.pub` — это тот файл, который нельзя никому отправлять, ни в чат, ни в репозиторий. Открытый ключ — с `.pub` — публиковать можно и нужно.
:::

## HTTPS или SSH

| | HTTPS | SSH |
|---|---|---|
| Первый вход | токен в браузере | один раз настроить ключ |
| Пароли | нужен Personal Access Token | не нужны |
| Корпоративные прокси | обычно проще | иногда блокируются |

Для личной работы SSH удобнее; для CI и скриптов часто берут HTTPS с токеном.

## Мини-практика

В терминале ниже — сценарий с уже настроенным remote. Пройди путь целиком, чтобы закрепить последовательность:

1. `git remote -v` — посмотреть, по какому адресу настроен origin.
2. `git status` — убедиться, что всё чисто.
3. `git push` — отправить изменения (в тренажёре пароль не спросят — как и с SSH-ключом).
4. `git log --oneline` — увидеть, что отправилось.
