# .gitignore: пароли и мусор

Главное правило: **в Git не должно попадать то, что не нужно другим людям**. Пароли, личные настройки, папки с весами моделей и `node_modules` — всё это живёт у тебя, а не в репозитории.

## Как это работает

**Как это работает.** Создаёшь файл `.gitignore` в корне проекта и перечисляешь шаблоны:

```bash
# секреты
.env
.env.*
*.pem

# зависимости и сборка
node_modules/
dist/
__pycache__/
*.pyc

# мусор редакторов и ОС
.vscode/
.idea/
.DS_Store
```

Git перестаёт предлагать эти файлы в `git status`, а `git add .` их не захватывает.

:::danger Если секрет уже закоммичен
`.gitignore` не стирает историю. Если пароль попал в коммит — его нужно **сменить**, а потом уже чистить историю. Считай, что он всё равно уже утёк.
:::

## Синтаксис

| Запись | Значение |
|---|---|
| `.env` | файл с таким именем в любой папке |
| `*.log` | все файлы с этим расширением |
| `build/` | папка целиком |
| `/config.yml` | только в корне проекта |
| `!important.log` | исключение из правил выше |
| `# текст` | комментарий |

## Посмотреть, что игнорируется

```bash
git status --ignored
git check-ignore -v .env     # какое правило сработало
```

## Готовые шаблоны

Не надо писать с нуля: у GitHub есть коллекция [github/gitignore](https://github.com/github/gitignore) — бери `Python.gitignore` или `Node.gitignore` и дополняй.

## Мини-практика

В терминале ниже есть `.env` с «секретом». Твоя задача:

1. `git status` — убедиться, что `.env` светится как untracked.
2. Создать `.gitignore` с правилами:

   ```bash
   echo ".env" > .gitignore
   echo "node_modules/" >> .gitignore
   ```

3. `git status` — `.env` больше не должен предлагаться.
4. `git add .` и `git commit -m "chore: ignore secrets and deps"`.
