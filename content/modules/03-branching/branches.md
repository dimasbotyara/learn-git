# Зачем нужны ветки

Ветка — это отдельная линия работы. Ты можешь делать эксперимент, ломать всё как хочешь, а `main` при этом останется целым и рабочим.

## Аналогия

`main` — это чистовой черновик, который всегда готов к сдаче. Ветка — отдельный лист с экспериментом: испортил — выбросил, не тронув чистовик.

## Основные команды

```bash
git branch                 # список веток, звёздочка = текущая
git branch feature         # создать ветку (и остаться на текущей)
git switch feature         # перейти в ветку
git switch -c feature      # создать и сразу перейти
git branch -d feature      # удалить (если уже влита)
```

`git checkout` — старый способ делать то же самое (`git checkout -b feature`). В новых версиях Git рекомендуют `git switch`, потому что у `checkout` слишком много обязанностей: он и ветки переключает, и файлы восстанавливает.

:::tip Запомни минимум
`git switch -c имя` — создать ветку и перейти в неё. Это 90% всех случаев.
:::

## Что происходит внутри

Ветка — это просто **указатель на коммит**. Когда ты коммитишь, указатель сдвигается вперёд. Поэтому создание ветки мгновенное и ничего не копирует.

```bash
git log --oneline --graph --all
```

Попробуй эту команду в терминале — увидишь «развилку», где ветки расходятся и сходятся.

## Именование

Общепринятая схема — префикс по типу работы:

- `feature/dark-theme` — новая функциональность;
- `fix/login-crash` — исправление;
- `docs/readme` — документация;
- `hotfix/payment` — срочная правка.

Так сразу видно, что за ветка, даже если открыто тридцать штук.

## Мини-практика

В терминале ниже репозиторий уже создан и есть один коммит. Сделай:

1. `git branch` — убедись, что ты на `main`.
2. `git switch -c feature/notes`.
3. `echo "идея" > ideas.txt` и `git add .`, `git commit -m "feat: add ideas"`.
4. `git switch main` — обрати внимание: файла `ideas.txt` здесь нет. Ветки изолированы.
5. `git log --oneline --graph --all` — посмотри на развилку.
