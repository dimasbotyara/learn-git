# git merge и как читать конфликты

Слияние — это перенос работы из одной ветки в другую. Обычно Git справляется сам, но иногда просит помощи. Это нормальный рабочий момент, а не катастрофа.

## Слияние без конфликта

```bash
git switch main
git merge feature
```

Возможны два сценария:

**Fast-forward** — в `main` не было новых коммитов, поэтому Git просто сдвигает указатель вперёд:

```
Updating 1a2b3c4..9f8e7d6
Fast-forward
 ideas.txt | 1 +
```

**3-way merge** — в обеих ветках были свои коммиты, Git создаёт отдельный merge-коммит с двумя родителями.

## Как появляется конфликт

Конфликт возникает, когда **одну и ту же строку** одного файла поменяли в двух ветках по-разному. Git не угадывает, кто прав, и честно показывает оба варианта.

```bash
git merge feature
# Auto-merging shared.txt
# CONFLICT (content): Merge conflict in shared.txt
# Automatic merge failed; fix conflicts and then commit the result.
```

В файле появляются маркеры:

```diff
<<<<<<< HEAD
версия из текущей ветки
=======
версия из ветки feature
>>>>>>> feature
```

## Как решать конфликт

1. Открыть файл и **оставить то, что считаешь правильным** (можно смешать оба варианта).
2. Удалить все маркеры: `<<<<<<<`, `=======`, `>>>>>>>`.
3. `git add shared.txt` — сообщить Git, что файл готов.
4. `git commit -m "merge: resolve shared.txt"` — завершить слияние.

Хочешь отменить всё и начать заново — `git merge --abort`.

:::tip Проверка победы
После `git add` конфликт считается решённым. Если передумал — просто правь файл заново и снова `git add`.
:::

## Читаем вывод Git

| Строка вывода | Что значит |
|---|---|
| `Already up to date.` | Вливать нечего, всё уже есть |
| `Fast-forward` | Просто сдвинули указатель, конфликтов нет |
| `Merge made by the "ort" strategy.` | Создан merge-коммит |
| `CONFLICT (content)` | Нужно руками решить конфликт |

## Мини-практика

В терминале ниже уже создан конфликт: одинаковый файл изменён в `main` и в `feature`.

1. `git merge feature` — увидеть конфликт (если ещё не начинали).
2. `cat shared.txt` — посмотреть маркеры.
3. Определиться с содержимым и перезаписать файл:

   ```bash
   echo "версия, которую выбрал я" > shared.txt
   ```

4. `git add shared.txt`.
5. `git commit -m "merge: resolve shared.txt"`.
6. `git log --oneline --graph` — убедиться, что слияние завершено.
